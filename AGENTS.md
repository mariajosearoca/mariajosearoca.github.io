# AGENTS.md — Rules for working on this site

This repository is Maria Jose Aroca Moscote's personal/professional website
(`mariajosearoca.github.io`). These are the standing rules any agent (human or
AI) should follow when editing or publishing content here.

## Never publish without explicit approval

- **Never run `git push`, create/merge PRs, or otherwise publish this site
  publicly without asking first**, even if changes are already committed
  locally. Publishing to GitHub Pages makes the site live at
  `mariajosearoca.github.io` for anyone to see.
- Never post content from this repo to third-party services (pastebins,
  diagram tools, social media, etc.).
- Never invent facts, job titles, dates, metrics, or credentials. All resume
  content must trace back to the CV or explicit instructions from Maria Jose.
  If something is unclear or missing, ask rather than guess or embellish.
- Never include sensitive personal data beyond what's needed for a
  professional site (no home address, no ID numbers). Phone/email should only
  appear if Maria Jose confirms she wants them public.
- Never add tracking/analytics scripts, third-party embeds, or external
  fonts/CDNs without asking first.
- Grades, salary, visa status, date of birth

## Always ask first before

- Pushing or publishing anything (see above).
- Changing the site's core structure (section order, navigation model) in a
  way that deviates from what was requested.
- Adding new pages, external links, or integrations not explicitly requested.
- Deleting or overwriting the CV PDF, the headshot photo, or any other source
  asset in this folder.
- Committing to git (only commit when explicitly asked).
- Before any git push or change on GitHub
- Before deleting or overwriting a file

## Style

- Tone: professional but approachable — not overly corporate, not casual
  slang.
- Visual style: clean, modern, Columbia-blue accent palette, generous
  whitespace, streamlined single-page navigation (anchor links / tiles rather
  than multiple separate pages unless asked otherwise).
- Code style: plain HTML/CSS (+ minimal vanilla JS if needed), no build step,
  no frameworks unless requested — this should stay simple enough to host
  directly on GitHub Pages.
- Content accuracy: resume content mirrors the source CV section order and
  wording closely; summarize/condense for readability but don't change facts,
  numbers, or dates.
- Keep file structure flat and simple (e.g. `index.html`, `styles.css` if
  separated out, `assets/` for images) unless the project grows enough to
  need more structure.
